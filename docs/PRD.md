# FF - DeepSeek Harness Web 产品需求文档

> 为 DeepSeek Harness 提供可快速适配的 Web 操作环境。

## 1. 背景与事实边界

DeepSeek 已公开确认其代码 Agent 评测使用了 `DeepSeek Harness minimal mode`，并标注该 Harness 将发布；截至 2026-08-12，官方尚未公开其最终产品形态、功能清单、安装方式和集成协议。来源：[DeepSeek API 更新日志](https://api-docs.deepseek.com/updates/)。

因此，本产品不复制或猜测官方 Harness 的内部实现，而是提前建设一套稳定的 Web 操作环境和兼容层。官方发布后，只需识别其真实接口并增加独立 Adapter，即可让用户通过统一 Web 界面使用已公开的能力。

## 2. 目标用户与核心问题

### 目标用户

- 希望通过浏览器而非纯终端操作 DeepSeek Harness 的开发者与技术用户。
- 需要清楚观察 Harness 执行过程、代码变化、审批请求和最终产物的用户。

### 核心问题

- 官方 Harness 的发布形态和协议未知，提前开发容易因错误假设返工。
- Harness 的任务过程包含消息、计划、工具调用、命令、审批、文件变化和产物，纯终端不利于集中观察与操作。
- 部分高级能力可能首发缺失或后续增加，固定页面会产生大量条件分支和重构。

## 3. 产品目标与成功信号

### 产品目标

1. 提供一条完整、可观察、可控制的 Harness Web 操作旅程。
2. 用统一 Adapter、事件和能力协议隔离官方实现的不确定性。
3. 在官方只提供交互式 CLI 的最差兼容情况下，仍能通过 PTY、文件观察和 Git Diff 完成首日基础接入。
4. 对后续出现的计划、记忆、子 Agent、Skills、MCP 等能力做到可发现、可扩展，而不是提前仿造。

### 成功信号

- 接入官方 Harness 时，核心 UI 与领域状态不引用任何官方专属字段。
- 官方适配工作集中在一个独立 Adapter 及其能力/事件映射中。
- 不支持的能力不会出现无效入口；未知事件不会导致页面失败，并可在原始事件视图中查看。
- 用户可完成“连接 → 工作区 → 会话 → 执行 → 审批/观察 → 查看结果”的 P0 旅程。
- 结构化接口不可用时，用户仍可通过 Web Terminal 操作 Harness，并同步查看文件变化与 Git Diff。

## 4. P0 核心旅程

```text
打开 Web 应用
→ 连接或启动 Harness，完成版本与能力探测
→ 选择本地工作区或导入 Git 仓库
→ 新建或继续会话
→ 输入任务并开始执行
→ 在时间线中查看消息、计划、动作、命令、错误与状态
→ 必要时批准、拒绝、停止或继续
→ 查看文件树、Git Diff、终端输出和生成产物
→ 结束任务或保留会话供后续继续
```

## 5. 功能需求

| ID | 用户需求 | 优先级 | 可观察结果 | 确认状态 |
|---|---|---:|---|---|
| REQ-001 | 连接或启动一个 Harness 运行时，并探测版本、连接状态与能力 | P0 | 顶部显示明确的探测、就绪、断连、不兼容或失败状态 | 已确认 |
| REQ-002 | 选择本地项目目录或导入 Git 仓库作为工作区 | P0 | 左侧显示当前工作区与文件树，Bridge 使用该目录启动会话 | 已确认 |
| REQ-003 | 新建、打开、继续、停止和结束 Harness 会话 | P0 | 会话列表和当前状态与真实运行时一致 | 已确认 |
| REQ-004 | 输入任务、引用工作区文件并接收流式结果 | P0 | 用户输入进入当前会话，增量消息和最终消息连续可见 | 已确认 |
| REQ-005 | 在统一时间线中查看 Harness 的计划、动作、工具调用、命令、错误和完成状态 | P0 | 不同执行事件按顺序渲染，未知事件显示为原始事件 | 已确认 |
| REQ-006 | 当没有结构化接口时通过 Web Terminal 直接操作官方 CLI/TUI | P0 | 终端可双向交互，进程退出、断开和错误均有明确状态 | 已确认 |
| REQ-007 | 对 Harness 请求的高影响操作进行允许或拒绝，并能取消当前任务 | P0 | 待审批状态阻止继续执行，用户决定被送回同一运行时 | 已确认，取决于官方能力 |
| REQ-008 | 独立观察文件变化并查看 Git Diff | P0 | 新增、修改、删除文件及具体 Diff 可见，不依赖 Harness 事件 | 已确认 |
| REQ-009 | 查看 Harness 生成的 Markdown、代码、图片、HTML 或普通文件产物 | P0 | 受支持产物可预览，不支持的文件可定位或下载 | 已确认 |
| REQ-010 | 刷新或短暂断连后恢复已持久化的会话时间线和诊断信息 | P0 | 已记录事件按原顺序恢复，运行时不可恢复时明确说明 | 已确认 |
| REQ-011 | 根据能力探测动态启用计划、重试、检查点、记忆、上下文压缩、子 Agent、用量、缓存、浏览器、MCP 和 Skills 等扩展能力 | P1 | 仅真实支持的能力出现；尚未结构化支持的内容进入通用动作或原始事件视图 | 能力槽位已确认，具体交互待官方发布后核实 |

## 6. 验收标准

- **REQ-001**：Given 尚未连接运行时，When 用户发起连接，Then 页面展示探测过程，并最终显示真实版本、能力和确定状态。
- **REQ-002**：Given Bridge 可访问本地文件系统，When 用户选择有效目录，Then 文件树显示该目录且新会话以其作为工作目录。
- **REQ-003**：Given 已连接运行时，When 用户创建、恢复、停止或结束会话，Then 会话状态与运行时结果一致且不会出现重复会话。
- **REQ-004**：Given 当前会话可接收输入，When 用户提交任务，Then 输入只发送一次，流式内容按顺序展示并收敛为完成消息。
- **REQ-005**：Given Adapter 连续产生已知与未知事件，When Web 接收事件，Then 已知事件按统一组件展示，未知事件作为 `raw` 展示且页面不崩溃。
- **REQ-006**：Given 运行时仅提供交互式 CLI/TUI，When Bridge 通过 PTY 启动它，Then 用户可以在 Web Terminal 完成双向输入输出并看到退出状态。
- **REQ-007**：Given Harness 发出审批请求，When 用户允许或拒绝，Then 决策只提交一次并解除或终止对应等待状态；取消任务可停止当前执行。
- **REQ-008**：Given Harness 修改工作区，When 文件变化发生，Then 页面无需依赖 Harness 事件即可显示文件状态和对应 Git Diff。
- **REQ-009**：Given Harness 产生一个可定位产物，When 用户打开产物，Then 支持的类型可预览，其他类型提供明确文件信息和获取方式。
- **REQ-010**：Given 会话事件已经持久化，When 页面刷新或 Bridge 重连，Then 时间线按序恢复；无法恢复运行时执行时显示真实终止或失联状态。
- **REQ-011**：Given 两个运行时返回不同能力集合，When 页面加载，Then 每个运行时只出现其真实支持的功能，核心旅程不受缺失扩展能力影响。

## 7. 明确不做

- 自行实现或冒充官方 DeepSeek Harness。
- 在官方发布前复制其未知的 Agent 循环、提示词、上下文策略、重试策略或多 Agent 编排。
- V0.1 开发完整的多 Agent、长期记忆、Skills、MCP、缓存或成本管理器；这些仅进入能力合同，真实交互待官方能力确认。
- 团队协作、组织权限、云端沙箱、计费、模型市场和完整在线 IDE。
- 把 Mock 数据隐藏成真实 Harness 执行结果。

## 8. 待核实

- 官方交付形态：HTTP/SSE/WebSocket API、SDK、JSONL CLI、交互式 CLI/TUI、桌面应用或其组合。
- 官方安装、鉴权、会话恢复、审批、事件流和扩展能力协议。
- 官方是否允许外部 UI 直接嵌入或只能通过本地进程/服务连接。
- 官方 Harness 对 Windows、macOS、Linux 的支持范围。
- 官方事件中哪些字段可以稳定映射为计划、动作、用量、缓存、子 Agent、Skills 和 MCP。
- 本产品具体前端框架、Bridge 语言、通信协议与本地持久化方案；下一轮技术方案讨论后定稿。
